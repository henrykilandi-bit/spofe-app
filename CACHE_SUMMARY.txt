🔒 SÉCURITÉ ET RÉSILIENCE

✅ Circuit Breaker Pattern
   • Détecte: 5 erreurs Redis
   • Action: Ouvre circuit → 30s pause
   • Récupération: Automatic reconnect avec backoff

✅ Memory Fallback
   • Quand: Redis indisponible
   • Durée: Jusqu'à 60 minutes
   • Graceful Degradation: Pas d'outage

✅ Multi-tenant Isolation
   • Chaque compagnie: cache:comp_1:*, cache:comp_2:*
   • Isolation: Complète, pas de data leak
   • Invalidation: Spécifique par compagnie

✅ Non-blocking Operations
   • SCAN vs KEYS: O(1) constant time
   • Invalidation: Asynchrone, non-bloquant
   • Performance: Zéro impact sur requêtes actives

✅ Admin Protection
   • Tous endpoints: Role-based (admin only)
   • Logging: Toutes les opérations
   • Audit: Traçable et monitored

🚀 DÉMARRAGE RAPIDE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Vérifier Redis
   redis-cli ping
   # PONG

2. Configurer .env
   REDIS_HOST=localhost
   REDIS_PORT=6379
   REDIS_PASSWORD=your_password (optional)
   REDIS_TLS=false

3. Démarrer l'application
   npm run dev
   # Cache initializes automatically

4. Vérifier la santé
   npm run cache:health
   # status: healthy

5. Voir les statistiques
   npm run cache:stats
   # hits, misses, hitRate, ...

6. Accéder à l'admin dashboard
   curl http://localhost:3001/api/cache/health
   # Response with stats

Problem: Circuit breaker open
Solution: Check Redis with "redis-cli ping"
  npm run cache:health
  grep "Circuit breaker" logs/error.log

Problem: Hit rate low (<30%)
Solution: Increase TTL or validate patterns
  npm run cache:analyze:patterns
  npm run cache:stats:watch

Problem: Memory fallback too large
Solution: Clean expired entries
  npm run cache:cleanup

Problem: Redis not responding
Solution: Restart Redis and check connectivity
  redis-cli ping
  redis-cli ping  # Should respond PONG
